# Learning record template

Make a personal copy of this file, date it, and preserve earlier entries. The [course map](COURSE.md) provides the module gates; this record stores evidence behind a pass decision. A checkmark without the original answer, corrected reasoning, and later retest is incomplete. The intervals below are a study aid, not a measured prediction of retention.


Passing the Python challenge lets an experienced programmer replace introductory syntax work in Module 15 with an advanced reproducibility or testing task. The Module 15 artifact and Gate C still apply. Options mechanics, mathematics, and safety scenarios must each be demonstrated independently.

```text

Exact incorrect step and corrected reasoning:

Artifact or code path, data version, and result hash if relevant:

```

For safety-critical errors, solve a *fresh* case after correcting the reasoning. Recheck important ideas after a day, about a week, and about a month, adjusting the intervals to actual results. Keep the first answer as well as the correction so progress is visible.

Observations from delayed quotes are suitable for practice but are not proof of an available live fill. When paper simulation begins, maintain the eight-week decision record and requirements in [the risk guide](RISK_AND_OPERATIONS.md) even if it spans more than one course module.

## A common review rubric

Score each dimension **0 = absent or wrong**, **1 = partly correct with an unexplained gap**, or **2 = independently reproducible and explained**. Save the reviewer's specific counterexample and the learner's response. A total score is useful for feedback; the module's stated gate still controls advancement.

| Dimension | What earns 2 |
| --- | --- |
| Contract and units | Exact series, premium multiplier, exercise deliverable, dates, dollars, shares, and assumptions are correct. |
| Calculation or code | A hand check and a clean rerun agree; boundary or adverse cases have been tried. |
| Decision and operations | Cash, shares, remaining options, order status, nonfills, fees, and funding are reconciled when relevant. |
| Evidence and interpretation | Source, timestamp, benchmark, failed alternatives, uncertainty, and permitted conclusion match the project. |

For Modules 1–12, any error about contract size, maximum loss, exercise, assignment, settlement, or funding requires a fresh correct case even if the total score is high. For Modules 13–26, a code pass with wrong timestamps, unsupported fills, or concealed variants fails the research gate. An independent reviewer should change one input or assumption and ask for a new explanation before signing off on a major gate.
