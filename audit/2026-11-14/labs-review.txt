CONFIRMED FINDINGS

L1 — Medium (P2): Ledger construction bypasses the integer/finite invariants enforced by trade methods.
Location: labs/options_lab.py:85–90 (Ledger fields), :109–127 (settlement); duplicated in course-app/public/labs/options_lab.py.
Evidence: Ledger(Contract('C100',100,'call'), cash=10000, option_qty=0.5).settle(110) succeeds and leaves cash=5000.0 and shares=50.0. option_qty=True likewise settles as one contract. Opening cash=float('nan') is accepted, and equity(...) returns NaN. This contradicts the broad statement in labs/README.md:40 that the implementation rejects fractional option quantities. Python type annotations do not validate dataclass initialization. trade_option validates new quantities, but cannot repair an invalid opening ledger.
Impact: learners reconstructing a ledger from imported positions can obtain plausible but impossible standard-option settlements, or silently nonfinite portfolio equity. The supplied default fixtures do not trigger it.
Suggested fix: add Ledger.__post_init__ to validate finite opening cash, non-boolean integer shares and option_qty (zero allowed), and validate at mutation/settlement boundaries if direct mutation remains public. Add a constructor regression case and ensure rejected operations leave state unchanged.
Minimal reproduction:
  l = Ledger(Contract('C100', 100, 'call'), cash=10000, option_qty=0.5)
  l.settle(110)
  print(l.cash, l.shares)   # 5000.0 50.0; should reject fractional option_qty

L2 — Low (P3): Quote validation permits fractional, boolean and nonfinite displayed sizes.
Location: labs/options_lab.py:246–254 (Quote), :264–274 (quote_flags), :318 (filled=min(quantity,size)); duplicate hosted Python source.
Evidence: q=replace(load_quotes(DATA/'quotes.csv')[0], ask_size=0.5) gives quote_flags(q)==[]; simulate_order(q,'buy',1,3) returns ModeledFill(status='modeled_partial',quantity=0.5,price=2.2,fees=0.5). ask_size=float('nan') also passes flags, and the same order reports a full fill. ask_size=True passes as valid size.
Impact: the public simulator can create a fractional standard-option fill or assume liquidity from an invalid quote. CSV loading uses int(), so the bundled CSV route is protected; direct Quote construction/replacement is not.
Suggested fix: explicitly require each visible size to be a non-boolean integer, with a separate absent/zero-size policy. Validate both sizes before computing fill quantities. Add cases for fractional, boolean, NaN and infinity sizes.
